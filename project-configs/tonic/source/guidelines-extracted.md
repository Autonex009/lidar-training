# Overview

- These instructions define how to annotate objects in LiDAR point cloud
  data using 3D cuboids (bounding boxes). Annotations must be complete,
  consistent, and tightly fitted to the object in every frame.

- The ontology covers different object classes across different groups:
  person, Dynamic Objects, and Static Objects. Every visible object from
  this list within a radius of 10m must be annotated in every frame
  where it appears.

- The goal of this module is to train annotators to **accurately
  identify and label** the dynamic objects like Human**,** Humanoid
  Robot, Forklift, Pallet Jack, Cart, AGV / AMR, Wheelchair, Vehicle and
  Static objects like Pallet, Tote, Bin, Rack, Shelf, Conveyor,
  Workstation, Table, Chair etc. with high consistency.

# General Instructions

- Draw 3D bounding boxes (cuboids) around all objects from the label
  list, and assign the correct label.

- Do not apply more than one cuboid to a single object.

- Check every cuboid in every frame to ensure all LiDAR points are
  contained within the cuboid.

- The cuboid center must be the geometric center of the entire object,
  including parts not currently visible.

- Cuboid orientation: the length axis must align with the object's
  direction of travel; the height axis points upward; the width axis is
  perpendicular to both.

- Object IDs must remain consistent across all frames in which the
  object appears. Do not switch IDs between objects.

- IDs must be unsigned integers (e.g. 0, 1, 2). The order they are
  assigned is not important.

- The cuboids should be properly aligned with the object in the 2D
  image. Please ensure the 3D cuboid fits the visible 2D object
  correctly.

# Required fields per object

Every cuboid must have:

- Track ID (persistent across frames, never reassigned within a
  sequence/camera)

- Class ID: one of the 22 ontology classes (Human, Humanoid Robot,
  Forklift, Pallet Jack, Cart, AGV/AMR, Wheelchair, Vehicle, Pallet,
  Tote, Bin, Rack, Shelf, Conveyor, Workstation, Table, Chair, Charging
  Station, Dock Door, Safety Barrier, Machines, Boxes)

- Occlusion state:

  - None = \>90% visible

  - Partial = 30-90% visible

  - Heavy = \<30% visible

- Motion state: Static / Moving (present on every class)

**Pre-labelled cuboids**

The pre-labels are cuboids generated by a model to assist with the
annotation process. While working on the tasks, annotators should
carefully review each pre-label and check whether it is relevant to the
objects covered under their respective branch.

- **If the pre-label is relevant:** Review the cuboid carefully, change
  its class to the appropriate ontology/class, and make sure it is
  properly aligned with the object across every frame.

- **If the pre-label is not relevant:** Delete the pre-label and
  continue annotating the other relevant objects in the task.

Please make sure that all pre-labels are reviewed rather than being
accepted as-is

**Regions of interest**

ROI: 0-5 needs to be perfect quality (5% error)\
ROI 2: 0-10 everything labelled\
ROI 3: \>10m is good but optional if lidar points are bad

# Human

> A person present in the scene, in any posture or activity (Standing,
> Walking, Running, Sitting, Kneeling, Bending, In-Wheelchair/ADA,
> etc.). Cuboid covers the full expected body volume, including any
> occluded portion.
>
> Cuboids shall encompass the expected physical body volume including:

- Head

- Torso

- Arms

- Legs

> For partially occluded humans, annotators shall estimate the hidden
> body portion and maintain a physically representative cuboid.
>
> Cuboids shall not be reduced solely to fit visible pixels.
